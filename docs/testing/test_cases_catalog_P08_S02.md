# Test Cases Catalog: Phase 08 · Sprint 02 - Automatic Game Recovery

## 1. Scope & Verification Strategy

This catalog specifies unit, integration, UI component, and property-based test cases for the **Automatic Game Recovery** feature. The test suite guarantees crash resilience, authoritative state snapshotting upon moves/undos/mode changes, automatic cleanup upon game completion, and robust recovery dialog workflows (Continue vs Discard).

---

## 2. Test Cases Matrix

| Test ID           | Test Category        | Target Component                               | Description / Scenario                                                                 | Expected Outcome                                                                                                                |
| :---------------- | :------------------- | :--------------------------------------------- | :------------------------------------------------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------------ |
| **`TC-RECOV-01`** | Positive Unit        | `GameSessionController` / `PersistenceService` | `makeMove()` committed on active session with persistence enabled.                     | Snapshot saved to `PersistenceService.saveActiveGame()` containing updated FEN, SAN history, turn, and timestamps.              |
| **`TC-RECOV-02`** | Positive Unit        | `GameSessionController` / `PersistenceService` | `undo()` called on active session with history.                                        | Snapshot in `PersistenceService` updated with truncated move history and restored prior FEN position.                           |
| **`TC-RECOV-03`** | Positive Unit        | `GameSessionController` / `PersistenceService` | `updateGameMode()` called to switch between PvE and PvP mid-session.                   | Active game snapshot updated with new `mode` and player configurations.                                                         |
| **`TC-RECOV-04`** | Positive Unit        | `GameSessionController` / `PersistenceService` | `loadFen()` called to setup custom board position.                                     | Active game snapshot updated with new FEN, cleared history, and updated timestamp.                                              |
| **`TC-RECOV-05`** | Positive Unit        | `GameSessionController` / `PersistenceService` | Game reaches terminal state (`checkmate`, `stalemate`, draw).                          | Recovery snapshot automatically cleared (`saveActiveGame(null)`).                                                               |
| **`TC-RECOV-06`** | Positive Unit        | `GameSessionController` / `PersistenceService` | Player resigns via `resign()`.                                                         | Game status updated to resigned and recovery snapshot cleared from storage.                                                     |
| **`TC-RECOV-07`** | Positive Unit        | `GameSessionController` / `PersistenceService` | Clock flag fall timeout via `timeout()`.                                               | Game status updated to timeout and recovery snapshot cleared from storage.                                                      |
| **`TC-RECOV-08`** | Positive Unit        | `GameSessionController` / `PersistenceService` | Players agree draw via `agreeDraw()`.                                                  | Game status updated to draw and recovery snapshot cleared from storage.                                                         |
| **`TC-RECOV-09`** | Positive Unit        | `GameSessionController` / `PersistenceService` | Session reset via `reset()` to starting position.                                      | Recovery snapshot safely cleared or set to fresh initial state.                                                                 |
| **`TC-RECOV-10`** | Positive Integration | `useGameRecovery` / `RecoveryService`          | Application launches with valid active game in storage.                                | `isRecoveryAvailable` is `true`, recovery metadata matches stored snapshot, and modal prompt is triggered.                      |
| **`TC-RECOV-11`** | Boundary Integration | `useGameRecovery` / `RecoveryService`          | Application launches with no active game or clean starting position (0 moves).         | `isRecoveryAvailable` is `false`, no modal prompt is displayed.                                                                 |
| **`TC-RECOV-12`** | Negative Integration | `useGameRecovery` / `RecoveryService`          | Stored state contains an activeGame whose FEN represents checkmate/stalemate.          | Detected as completed game; recovery prompt is suppressed and stale state is purged.                                            |
| **`TC-RECOV-13`** | Negative Integration | `useGameRecovery` / `RecoveryService`          | Stored state contains malformed FEN, invalid JSON, or broken schema.                   | Corrupt state is safely discarded; falls back to default clean game with zero runtime exceptions.                               |
| **`TC-RECOV-14`** | Positive UI / Hook   | `GameRecoveryModal` / `useGameRecovery`        | User clicks "Continue Game" in recovery modal.                                         | Active session restored (FEN, history, turn, clocks, player names, orientation), modal closes, game is playable.                |
| **`TC-RECOV-15`** | Positive UI / Hook   | `GameRecoveryModal` / `useGameRecovery`        | User clicks "Discard / Start Fresh" in recovery modal.                                 | Active game snapshot deleted from storage (`saveActiveGame(null)`), modal closes, initial fresh session remains active.         |
| **`TC-RECOV-16`** | Positive UI          | `GameRecoveryModal`                            | Verify modal rendering, accessibility attributes, keyboard trap, and test IDs.         | Contains `data-testid="game-recovery-modal"`, `data-testid="btn-continue-game"`, `data-testid="btn-discard-game"`, aria labels. |
| **`TC-RECOV-17`** | Property Fuzzing     | `RecoveryService` (fast-check)                 | Generative fuzzing of game sessions with random legal moves, serialized, and restored. | Restored game position FEN, turn, and move history match pre-serialization session with 100% fidelity across all iterations.    |
